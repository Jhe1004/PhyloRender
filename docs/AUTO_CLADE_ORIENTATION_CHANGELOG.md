# 自动分组名称方向与紧凑避让（2026-11-03）

## 用户要求与共享契约

普通树、Dating和云图的组名默认使用`label_orientation: "auto"`。
对齐的括号优先使用整体顺时针旋转90°的名称，纵向范围相交时使用不同列。
普通树的nearby括号保留局部位置，横排能利用现有名称空隙时保留横排；否则比较安全横排与竖排占据的右侧范围。
测量到的样品文字边界参与避让，组间挪动后再次检查样品障碍。
这不是保证全局最优的排版搜索，不通过缩字、扩大样品行距或改变分组成员来压缩图幅。

默认值与可接受方向唯一声明在`figure-contract.cladeLabelOrientation`，schema枚举和桥接直接复用。
网页保留原横向／竖向radio的ID并新增自动选项。旧配置明确horizontal/vertical时保留该选择；省略方向的新配置进入自动模式。
导出保留auto，而非把派生后的横／竖结果写回配置，因此重排、切换工作区和字体改变后仍能重新选择。
手动方向继续受尊重，原有分列算法的顺序和常数不变。

## 模块边界

`core/clade-layout.js`只接收已测量的分组条目、末端文字边界、对齐模式和画布高度，返回复制的布局条目与所需宽度。
无DOM、原树、应用state、文件系统、网络或科学引擎。模块登记在架构清单，浏览器在app之前加载；现有core静态白名单、构建指纹及Docker COPY覆盖该文件。
app只读取当前文档分组、测量文字、整理端口并委托；Dating和云树显式传入样品实际边界与本次高度。
预估右侧空间同样提供样品文字测量值，不依赖上一次文档画布尺寸。
旋转、错列只改变显示几何，不改变原始名称、拓扑、支持率、年龄、HPD、四类统计或科学缓存身份。
组名字号继续遵循原有样品字号+3u自动规则，明确字号及富文本分段样式保持。
