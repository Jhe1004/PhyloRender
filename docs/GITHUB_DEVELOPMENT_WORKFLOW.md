# GitHub正式开发流程

## 唯一正式仓库

- GitHub：`Jhe1004/PhyloRender`
- 可见性：private
- 默认分支：`main`
- `main`只保存已经通过项目门禁、能够继续开发的基线。
- 111号以前的本地编号阶段只读保留，只作为历史档案。后续不再建立新的编号源码阶段，Git提交、PR和版本标签是唯一开发时间线。

## 每次开发

1. 从最新`main`建立一个短期分支，名称使用`feature/简短名称`、`fix/简短名称`或`maintenance/简短名称`。
2. 开始前记录`git status`和基线提交。不得覆盖、重置或冒充用户已有改动。
3. 一次分支只处理一个明确问题；科学逻辑、界面整理和无关重构不得混在同一提交。
4. 修改代码时同步更新直接测试、schema、agent说明和必要文档；网页与MCP共用同一契约。
5. 至少运行`node tools/check-project.cjs`。涉及浏览器、MCP、导入、布局、状态或导出时运行`node tools/check-project.cjs --integration`。涉及原生科学程序时再运行`--native-science`。
6. 提交信息使用英文类型和清楚内容，例如`fix: preserve dated-tree age source`。不要使用“update”“changes”等无法判断内容的说明。
7. 推送分支并通过Pull Request合并。PR必须写明需求、不变量、实际改动、测试与退出码、构建ID、未验证范围和部署状态。
8. CI和审查通过后才合并到`main`。合并代码不自动部署，不自动重启本地或公网MCP服务。

开发、验证和提交都在同一仓库完成。不得为一次普通修改复制整个仓库或在项目父目录创建新的递增编号文件夹；需要临时对照时使用Git分支、worktree或系统临时目录，并在完成后清理临时工作区。

## 禁止进入Git

- `.env`、访问令牌、私钥、密码和真实Bearer token。
- `node_modules`、`.venv`、缓存、日志、临时目录和运行时结果。
- 用户未授权公开的原始树、名称数据和生成图稿。
- 独立的`taxon-name-model/`项目及其第三方训练环境。
- 仅适用于某台电脑且许可证不允许再分发的二进制文件。

`.env.example`只允许保留变量名和明确的无效占位值。发现秘密进入Git历史后，不能只删除文件；必须立即废止秘密并清理历史。

## AI agent提交前检查

- 完整阅读根`AGENTS.md`和与本次变更直接相关的changelog。
- `git diff --check`无空白错误。
- `git status --short`中没有意外文件、缓存或用户资料。
- 生产清单和schema检查通过。
- 验证结果来自真实命令退出码，不把目录存在、测试启动或截图当作完成。
- 未得到明确授权时，不推送、不创建PR、不部署、不重启共享服务。
