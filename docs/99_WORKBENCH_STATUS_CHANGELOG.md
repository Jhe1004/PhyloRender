# 99阶段：工作台统计与常规提示精简

从98号已验收源码建立独立开发副本。用户要求移除设置标签下方的“末端／节点标注／遮挡”统计，以及定根、导入成功等常规提示，使标签页后面直接显示设置内容。

## 界面策略

- 统计栏、引导提示计数和问题定位状态放入永久hidden、aria-hidden的内部诊断容器，在四工作区所有标签页中均不占显示空间。
- 保留原ID和计数更新，网页渲染器、导入快照、MCP检查和碰撞报告继续读取同一结果。隐藏界面不能删除检查或改变科学统计。
- `showMessage`继续写入文字、error类和role；普通status信息隐藏，有正文的error消息显示为alert。导入失败、无效配置、数据错误继续显示并滚动到可见位置；成功的GUI重试清除旧错误提示。
- 字体缺失／实际字体替代提示不在本次红框内容中，继续保留。各输入卡片中的科学单位、校准及不支持模型说明也保留。

app.js只修改原hidden赋值条件，没有新增全局状态或另一套消息模块。没有修改CSS、科学输入、参数、布局算法、配置或MCP契约。隐藏容器只作用于工作台，SVG导出样式不变。

## 验证

专项`workbench-status-visibility.mjs`进入完整集成门禁。四工作区所有可见标签页与1440／820／390视口中，统计和常规消息均不显示，设置标题仍可见；内部末端计数仍非零。导航和提示策略不改变完整配置或SVG。每种模式上传实际无效配置，检查alert可见且旧配置保留；再从同一GUI入口上传有效配置，检查错误清除且成功信息不再占据界面。

旧统计栏实际可见的红色反例保留。首次专项误用直接MCP加载助手作GUI错误重试，它不负责发出GUI成功消息；改用同一个实际文件入口后重查，不能以手工隐藏错误通过测试。

基础、完整集成、21组新旧SVG与完整PNG精确对照，以及报告实测均按本阶段verification.json和实际退出码判断。SVG只排除metadata，不放宽其他属性、字体、坐标、图层或像素。

未部署、推送、重启共享服务或新增其他平台／Docker／安装包／许可结论；没有重跑73MB真实基因树集合，88号历史PNG差异根因未解决。
