# 94阶段：基因云层继承主树分组颜色

基线为93号已验收源码。只改变云层的分组颜色，不更换布局、定年、统计、默认透明度或科学匹配规则。历史目录不改，服务不自动切换。

## 用户可见行为

基因分支按其完整后代样品在物种树中的最近共同祖先归色。该祖先处的主树有效分组颜色，就是这条基因分支的颜色。组内的基因拓扑可以不同；不要求和物种树完全相同。最近共同祖先未分组时，仍用原灰色。不能按多数样品、类群大小或RGB相等决定归色。

嵌套分组遵循主树的颜色继承：完全落入子组时用子组颜色；横跨子组但仍在已着色父组内时用父组颜色。分属于不同未着色父组的分支不强行染色，即使两个组碰巧选了相同颜色。

单样品分组同样生效。隐藏物种树后仍使用它的分组参考；清除分组后云层恢复灰色。饼图颜色仍表示原四类统计，不继承分组色。颜色表示用户分组归属，不证明拓扑一致或生物学过程。

## 责任边界与效率

- core/cloud-group-colors：只读已验证且身份已对齐的物种树、基因树和有效颜色快照，建立原始样品索引及二进制祖先索引，返回新建的基因节点颜色Map。没有DOM、IO、定年、统计或全局缓存。
- render/cloud-tree：一轮渲染只建一次主树颜色参考，逐棵基因树取得颜色；继续使用93号共有节点行锚点和原布局。
- render/cloud-branches：显式区分物种树编辑目标与基因云层。基因枝线只加stroke，不加物种节点点击ID；未着色分支保留原继承灰色。
- app：只接线、更新颜色来源metadata；中文工作台解释自动继承规则。MCP继续使用同一渲染器和已有clades配置，不增加另一套算法或默认选项。

参考和归色逐节点yield，可由现有协作调度取消。颜色输入在参考生成开始时复制；没有半成品结果或颜色缓存。每棵树的颜色计算为节点遍历加最近共同祖先查询，不枚举所有基因后代集合来做生产归色。

## 验收规则

新增直接模块和组合反例，覆盖组内独有基因类群、跨组、嵌套、单样品、相同RGB但不同组、颜色快照、未知身份拒绝、取消及基因独显。网页实际分组对话框与颜色事件后导出配置，走真实MCP协议，逐属性比较六组SVG，只去metadata。

原modular-equivalence严格门禁保持不变，其失败记录保留；新增颜色专项不是行为等价重构。新的cloud-color-equivalence对每条云层分支用独立集合包含关系核对颜色，仅允许核对通过的stroke新增，其余属性、文字、字体、层序、坐标继续精确比较。未受影响图件PNG仍比较完整字节，受影响图件明确记录预期颜色变化，不能称为原PNG完全一致。

真实99样品／35棵基因树另逐条检查6,860条枝线，三种排列下的归色和科学输入不变。仍执行完整门禁、原生专项与真实13,797棵输入的稳定性检查；有效统计树与云层子集分别报告。实际结果以本阶段verification.json、命令退出码和构建ID为准。

当前仅macOS arm64验收；未部署、推送、重启共享服务、更新个人Skill、构建Docker或批准发布许可。88号历史PNG差异根因未在本轮调查。
