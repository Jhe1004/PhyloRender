# 自动比例与真实行距（2026-11-11）

用户确认普通树、Dating与云图默认以高为宽的1.25倍为目标，少样品适当舒展，多样品保持紧凑，双树保留横向偏好。字号、来源、配色和全部科学输入不改。

## 规则

- 现有实际字形高度及最小间隙仍构成基线；不再把48样品的基线间隙当作所有图的最终行距。
- `figure-contract.automaticRowLayout`唯一声明目标1.25、舒展上限3 em和80–120样品的平滑收紧区间。现有绝对行距72 px上限继续有效。
- 以本次实际画布宽度、自然高度、样品行数和字体快照计算需要的额外行距；高度增加量等于真实行间隔数乘行距增加量。不是加空白上下边，不拉伸字体或成图，也不把节点标注的碰撞当作增大样品间距的理由。
- 已达到目标或更高的图不再增加高度。极少样品被舒展上限保护，允许未达到1.25，避免空洞。
- 双树不增加这项竖向舒展，保留原有横向偏好和密集时的文字可读性；不为强制横版重叠文字、缩字号或突破1000单位画布与物理尺寸契约。
- 只在自动行距且比例模式为auto时生效。手动行距、content及明确比例不被新规则覆盖；同一输入反复绘制不累积拉伸。
- 自动增加的高度对齐至本机Chromium布局的1/64 px子像素格，实际行距同步反算且不超过上限。避免小数viewBox与CSS视口之间的微小缩放改变字形测量，导致拟合后又变宽；密集、手动及未舒展输入保持原几何。此精度由同一共享契约声明，不是新增用户选项。

## 共用实现

普通树、time-tree和cloud-tree共用planAutomaticRows。后两者通过显式planRows端口读取纯函数，几何只使用本次快照。Dating时间轴、云树共有节点锚点、分组和标注均跟随真实行坐标，不修改年龄、HPD、分支长度、统计、身份或来源单位。

派生currentLayoutInfo记录实际tipSpacing、基线和源树引用，恢复后的读数使用恢复控件，避免失败图或前一个工作区的行距污染当前文档。core/figure-report统一输出automatic_row_layout；配置仍使用现有automatic_tip_spacing与行距字段，不新增schema选项。MCP、网页和Skill说明同步；Agent只启用自动间距，不手工发送1.25比例或行距覆盖来冒充新默认。

云图的底部时间内容边界随行距增量一起移动，图例的安全页脚读取拉伸后的边界。完整回归中的少样品、大时间轴字号反例验证图例不覆盖时间轴；紧凑分组标题反例显式固定原行距，继续验证真正重叠时必须避让。
