# 93阶段：云树共有节点纵向同步修复

基线为90号已验收源码；92号诊断仅作为反例与测量证据。本轮不是行为等价重构：基因云层的纵向坐标有明确的预期变化，其余科学输入和物种树布局必须保持。

## 修复规则

先完成物种树的最终布局，再以完整后代样品集合匹配共有类群。共有基因节点（包括根）使用对应物种节点的最终纵向坐标，不能再次被基因树独立避让移动。不用类群大小、显示名或临时节点ID跨树匹配。

基因树独有的节点仍用原候选顺序与评分避让；末端行位置不变。矩形物种树和只显示基因云层时，也使用本次物种树布局作为参考。不得把不相同的类群强行叠到物种树上。

固定坐标只允许属于当前树的内部节点，必须是有限数值且位于本节点后代样品的纵向跨度内；错误明确报 CLOUD_INVALID_ROW_ANCHOR，不静默忽略、钳制或移动末端。年龄和横向坐标不由此规则修改。

## 模块与取消

- cloud-tree.js：纯派生共有类群坐标和协作避让；对共有节点采用硬约束。逐内部节点收集参考和匹配表，继续让出执行权。
- render/cloud-tree.js：先得到物种树最终坐标，再把本次参考传给每棵基因树。没有另一份网页或 MCP 算法。
- render/cloud-branches.js：输入锚点复制成此次快照。缓存键包含每个节点的锚点状态／数值；未知身份不得利用缓存别名命中。只有搜索完整结束后才缓存，取消不发布半成品。

没有增加工作台选项或改变 figure-spec。共有节点对齐属于 display_alignment，不是独立基因共祖时间推断。PhyParts 四类计数、分母、树拓扑、支持率、枝长和定年结果保持不变。

## 强制回归

`tests/cloud-row-anchors.test.cjs` 包含不依赖本机示例缓存的9末端非对称反例：共有年龄本来一致，独立布局仍会产生36 px错位；加入硬锚点后，三种排列和两种树形都必须逐点相等。不得把这个反例改成对称的小树，或只检查末端。

实际网页／MCP协议对照另执行 `node mcp-server/tests/cloud-row-parity.mjs`，3种排列×2种实际字号的六组SVG只排除metadata，保留全部data属性、字体、层序和坐标。界面在叠加基因树时原本强制使用三角分支，不能把被禁用的矩形选项冒称实际矩形云层验收。默认集成中的 `cloud-ladderization.mjs` 也核验真实示例的共有内部端点，不再只检查末端。

直接模块红／绿反例覆盖硬约束、精确类群匹配、无效锚点、缓存失效、输入快照、取消及矩形／三角／基因独显组合。实际 DOM 测试必须核对共有内部节点，而不只检查末端对齐。

真实99样品、35棵基因树在3种排列、3种行距、2种物种树形的18组测试中核验所有共有节点、末端和科学输入。还需完整回归、原生专项、网页／MCP严格图件对照，以及13,797棵真实输入的稳定性检查。

图件对照必须保留所有属性与原断言。未改工作区和关闭云层的图应精确一致；受修复影响的云层只允许枝线纵坐标改变，不能把整个云树图忽略后宣称行为等价。验收结果以本阶段 verification.json、命令实际退出码及构建ID为准，不以本文存在为准。
