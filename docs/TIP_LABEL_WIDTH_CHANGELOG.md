# 样品名默认宽度上限与横向字形压缩（2026-11-03）

## 用户要求与含义

2026-11-04用户认为固定画布比例压缩过重，确认改用样品名自然宽度中位数：上限 = 中位数 × 1.25。此规则替代旧1/3及0.8/3整图比例，不叠加旧上限。
这是明确的字形宽高比变化，保持文字高度、字号、全文、斜体／正体分段、颜色与编号内部下划线；短名称原样保留。
适用于普通树、Dating、云图及双树；双树将两侧实际显示的名称合并计算（同名出现两次即计两次）。偶数取中间两项均值；零宽字形不参与，没有正宽度时不压缩。单名称或全部等宽时保留自然比例。
先按当前显示名、字体与字号测量尚未压缩的字形；组名不参与中位数。印刷毫米和DPI不决定该上限。
此规则不截字、不换行、不修改原始身份，也不通过缩字号实现。既有明确字号仍决定文字高度。

## 实现与边界

- figure-contract.tipLabelWidth唯一声明比例；maximumTipLabelWidth显式接收自然名称宽度数组，schema与能力说明同步。
- render/tip-width.fitAll先恢复整批自然宽度，再调用共享中位数规则；fit读取传入SVG文字的字形边界与长度，通过textLength和spacingAndGlyphs调整横向比例。
  斜体字形边界不同于advance时，再测量实际结果；重复调用先清除本模块的派生压缩属性，不累积压缩。
- app的fitTipLabelWidth只委托；另外三个渲染器使用同一显式端口。
  文字先连接SVG获得真实字体，再压缩，随后才测量分组、节点避让或双树连线。预估宽度也使用同一共享上限。
  普通／Dating／云图的空间预留在临时隐藏SVG组中测量相同文字与样式，并调用同一拟合端口；完成或失败均移除临时组。不能用Canvas advance代替实际字形边界，否则斜体边缘会使中位数上限及组名预留不足。
- 双树两列都很长时，保留原连线通道与外边距，以剩余正宽度分配两棵树的横向跨度。
  只在名称已被压缩时允许显示树体低于原预留最小跨度，不修改原始枝长或科学含义；短名称沿用旧规则。
- 压缩属性是当前SVG派生显示信息，不新增文档字段、控件、用户身份映射或科学缓存参数。
  字体、分组、支持率、年龄、HPD和四类冲突统计不由该模块修改。
- 新模块登记架构清单，index在app之前加载；现有render静态白名单、构建指纹和Docker COPY覆盖。
