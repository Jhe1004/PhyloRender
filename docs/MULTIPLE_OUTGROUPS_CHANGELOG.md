# 基因树多外群兼容（2026-11-02）

原基因树准备代码只能从物种树二分根旁识别一份末端外群，因而会拒绝具有外群类群的合法物种树。
本次增加显式外群列表，不按根两侧的大小、顺序、属名或显示名称猜测外群。

- 网页“自动基因树冲突统计 → 统计选项与结果文件”增加逐行填写原始样品名称的入口。
- MCP／配置使用 `options.cloud.phyparts_outgroups`，类型为原始名称数组，默认空数组。
  空数组保持原单叶外群识别；多外群必须明确填写。
- 外群必须恰好对应物种树现有二分根的一侧。物种树原根、拓扑、枝长及已导入年龄不变。
  `rooting.outgroup` 在云图中继续拒绝，不能把基因树定根参数当作物种树重定根。
- 基因树允许缺少部分外群；实际出现的全部外群必须由一条边与其余样品分开。
  没有任何指定外群，或实际外群无法形成完整分支时，逐棵记为 `unrootable`。
  不选择其中某一份来规避冲突，不剪样品，不按树的原始绘制方向猜根。
- 基因树用原共享边定根实现创建派生副本，支持率保留在对应无根分支，边长总和及末端间距离不变。
  已在正确二分根位置的输入保留原根。
- `phyparts_root_policy=input` 不能同时携带非空外群列表。重复、不存在或跨根两侧的名称明确报
  `PHYPARTS_OUTGROUP_INVALID`，配置导入失败恢复完整模型、控件和图件。
- 所有输入逐棵核验；可比较的完整／部分样品基因树进入原四类冲突引擎。
  云层额外要求完整样品集合及合格 ML 枝长，不能把云层数量当作统计分母。

`core/gene-rooting` 通过工厂显式接收身份、输入与共享边定根模块，无 DOM、网络、文件系统或应用状态。
`cloud-tree` 保留兼容委托，`gene-preparation` 在同一 Worker 调用该政策。
外群列表进入科学缓存键；配置往返、MCP schema、能力说明、网页及 skill 同步。
新模块已登记架构清单；网页与 Worker 的加载顺序明确，现有 core 静态白名单、构建指纹和 Docker COPY 覆盖它。
本次为合法输入兼容修复，没有更换冲突统计算法或云树 `display_alignment` 含义。

直接反例见 `tests/multiple-outgroups.test.cjs`，保留单外群旧测试。
