# Offline macOS arm64 native build

This recipe builds treePL, ADOL-C 2.6.3, NLopt 2.4.2 (static) and LLVM OpenMP
20.1.8 from retained sources. It does not read the historical precompiled libomp
or copied omp.h. The header is generated by the OpenMP build. Complete terms and
corresponding sources remain in the retained native source/license bundle and
`vendor/native-sources/`; see `THIRD_PARTY_NOTICES.md`.

Requirements: macOS arm64, Apple Command Line Tools (`clang`, `clang++`, `make`,
`xcrun`, `otool`, `install_name_tool`, `codesign`), Python 3.9 or later, CMake
**3.31.6**, and 2 GiB free space. The validated environment used Apple clang
21.0.0 (clang-2100.1.1.101), macOS 26.5 SDK and CMake 3.31.6. These tools and the
SDK are prerequisites, not claimed source-rebuilt components. Provide CMake
explicitly; no global installation is performed. Once prerequisites are present,
the build is offline and does not require Homebrew or Conda.

```sh
python3 tools/build_treepl_macos.py --work /tmp/phylorender-native-build \
  --cmake /path/to/cmake-3.31.6/bin/cmake
```

Use a NEW directory with no whitespace. The checkout may contain whitespace.
Inputs are verified against `tools/native_build_manifest.json`; archive extraction
rejects traversal, absolute paths, links, duplicate names, special files and
excessive sizes before creating a target. Apple metadata is counted and omitted.
Source archives and historical numbered-stage binaries are never modified.

`tools/openmp_build.py` builds the official OpenMP and shared-CMake component
archives with Apple clang, arm64 and deployment target 11.0. CPU OpenMP is enabled;
GPU offloading, profiling and OMPT tools are disabled. Apple clang supplies its
compiler runtime. The retained Conda compiler-rt patch documents the historical
Conda package; this Apple-clang build neither applies that patch nor claims to
have compiled the auxiliary compiler-rt archive.

The recipe uses two jobs, normal priority, a 30-minute total command deadline and
10-minute per-command ceiling, all through `process_supervisor`. A compiler wrapper
restores Apple's `-Xpreprocessor -fopenmp` form for old libtool. Autotools installation
uses `DESTDIR` before copying the private prefix. Reproducible settings include
source prefix maps, SOURCE_DATE_EPOCH, ZERO_AR_DATE and deterministic linking.
After configure checks finish, OpenMP and the generated ADOL-C libtool recipe use
stable `@loader_path` IDs before final links. This prevents temporary-path-sized
Mach-O headers and UUID differences. Generated treePL debug flags are set to -g0;
no scientific source is changed.

`portable/` contains treePL, libadolc.2.dylib and libomp.dylib. Dependency allowlists
and fixed-identifier ad-hoc signatures with no timestamp are verified. This is not
Apple notarization. `commands.json`, `logs/` and `build-receipt.json` retain commands,
environment, tool hashes, compiler/SDK, exits, input/output hashes and failures.
Retries use another new directory; failed runs remain for inspection.

On 2026-11-01 two clean builds at different-length paths produced byte-identical
complete files for all three outputs. Their hashes are recorded in
`vendor/native/macos-arm64/manifest.json`. The current software uses this validated
bundle; the build tool itself never installs or activates its results. Activation
was a separate repository change after managed computation checks. Four-thread
OpenMP reduction passed five times. A four-tip synthetic calibration and 57-tip ML
gene-tree computational reference produced exact Newick output versus the
historical bundle. These checks are not universal scientific equivalence.

To reproduce, build twice under the recorded compiler/SDK/CMake and compare the
complete files using SHA-256. Rebuilding with a different toolchain is a new
candidate requiring validation; matching the historical precompiled file bytes
is not promised. Linux follows `mcp-server/Dockerfile` with separately recorded
system dependencies; macOS evidence does not source-rebuild those packages.
Windows is not validated by either recipe. See `docs/REPRODUCIBILITY.md`.
