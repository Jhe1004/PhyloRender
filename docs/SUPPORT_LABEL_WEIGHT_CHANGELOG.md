# 支持率标签字重统一（2026-11-02）

用户要求所有支持率标签统一服从粗体开关，默认不加粗。

原先普通树、复合支持率和双树对照中，只要显示文本包含短横线
`–` 或 `—`，标签就会附加 `support-threshold-mark`。该 CSS 类硬编码
`font-weight: 800`，覆盖了默认的 `--support-font-weight: 400`，也覆盖了
用户粗体开关指定的 `700`。因此 `58.0/–` 比 `100.0/0.9` 更粗。

本次仅删除该类的强制字重，使其与其他支持率标签共同继承
`.support-label` 的 `--support-font-weight`：关闭／默认为 `400`，开启为
`700`。原有白色描边、阈值替换、字段选择、原始数值、满支持分类和
主树／附加树匹配均保持不变。没有新增参数或修改科学数据。

回归入口为 `mcp-server/tests/node-weight-default.mjs`，覆盖纯低支持率
短横线、复合列、附加来源未匹配和双树对照。测试实际标签的计算字重，
并检查粗体开关的关闭→开启→关闭、独立 SVG 与 MCP 输出，不再只检查
SVG 根元素的 CSS 变量。

修复前，新增反例在默认短横线标签上复现 `800 != 400`。验证命令、
输出和实际图件存入 Git 忽略的 `mcp-server/var/support-weight-fix-20261102/`。
源码修改不会回写历史图件。由于原图配置已经是粗体关闭，MCP 正确拒绝
无设置变化的编辑；本次使用完全相同的输入和配置新建修复后图件，保留原图。

`node tools/check-project.cjs --integration` 均退出 0。基础门禁包含
396 项 JavaScript、15 项状态／接口和 27 项 Python 测试。检查真实
工作台、独立 SVG 和 MCP 输出的关闭→开启→关闭字重为 400→700→400，
