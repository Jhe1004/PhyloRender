# 96阶段：树形纵横双向拉伸入口修复

本阶段从95号已验收源码建立新副本。它修复的是设置入口不完整，不是新建一套纵向布局算法。

## 原因

纵向拉伸原本由共享的 `tip_spacing` / `tip_spacing_em` 控制，网页、配置和MCP已经使用同一参数。样品名称工作台重构时，`app.js` 在页面启动后把原纵向控件从“树形”页移到了“样品名称”页，因此“树形”页只剩横向拉伸。

## 修复

- 删除运行时移动控件的代码，纵向拉伸回到“树形”页。
- 同一个“树形拉伸”面板先显示纵向拉伸，再显示横向拉伸。两者均使用25–400%、滑条和减/数字/加精确输入。
- 普通树和Dating树在树形页显示两个方向。云树和双树冲突图保留原有纵向间距能力，也改到树形页；它们各自的横向坐标仍由现有专用布局管理，本阶段不冒充已接入普通树的横向缩放算法。
- 样品名称页不再重复放置树几何控件，不产生重复ID或两份状态。

## 不变量

- 默认100%的SVG/PNG应与95号完全一致。
- 纵向拉伸只改变末端中心间距和由此派生的高度；不改横坐标、字号、末端顺序、拓扑、枝长、支持率、时间或PhyParts统计。
- 横向拉伸不改变纵向间距。
- 网页、导出配置和MCP继续共用既有参数和渲染路径；没有新增或变更API字段。

## 验收

正式结果以同阶段 `02_验证记录/verification.json`、构建清单、退出码、真实SVG/PNG及图文报告为准。本文是后续agent的变更边界，不单独作为通过证据。
