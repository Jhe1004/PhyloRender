# 97阶段：节点标注位置调整公共入口

从96号已验收源码建立独立阶段。此次只整理公共操作的位置和中文说明，科学方法、布局评分、参数、MCP契约和默认图件保持原样。

## 用户可见变化

- 将唯一的`node-label-controls`从设置标题下方移到工作台的最后一个子节点。它没有`data-settings-page`，不归属于样品名称、树形或其他单独栏目。
- 上方保留分隔线、独立标题“节点标注位置调整”。按钮统一显示“自动调整节点标注位置”；设置页说明、帮助文字和任务标题同步改名，不再指向旧的“标注页”按钮。
- 普通树、Dating树、双树冲突图的选项继续调整节点数字位置、设定范围内字号和引导线；保留当前末端字号、字体、行距及其他显示设置。手动节点标注位置仍按既有操作重新计算。
- 云树也显示同一个公共按钮，说明明确为重新安排节点饼图。云树不显示未接入其饼图算法的数字字号及引导线开关；隐藏只影响界面，原配置字段仍按既有契约保留。
- 参数变更与节点标注调整仍使用已有协作渲染和事务。没有复制算法、改变候选顺序或重新运行定年／统计。

## 技术边界

公共区域在HTML中固定放在末尾，使用仅作用于自身的内联分隔样式。没有修改styles.css或ui-shell.css；当前SVG导出会嵌入整份样式表，修改工作台CSS也会改变SVG文本。后续如需拆分导出CSS，应另建任务和严格反例，不能在此次界面修改中忽略样式差异。

`reset-labels`、`auto-labels`、`leader-lines`等内部ID与MCP字段不改名，旧配置与调用方继续兼容。app只增加一行按工作区更新公共说明，体量上限不提高。

## 验证要求

专项`mcp-server/tests/node-annotation-action.mjs`通过真实浏览器遍历四工作区、可见标签页和1440／820／390视口，检查唯一入口、末尾位置、展开栏目后的分离、无旧按钮文案及云树无效选项隐藏。每种模式真实点击一次，再核对原始输入、完整options和字号／间距控件。专项进入完整集成门禁。

原界面位置断言更改为合法的新位置；布局行为断言保持。新旧21组SVG仅排除metadata，其余属性、字体、图层、坐标和完整PNG继续精确比较。最终结果按本阶段verification.json、command-exits.json和构建ID判断。

本轮不解决88号历史PNG差异根因，不增加其他平台、Docker、安装包或许可结论；不部署、推送或重启共享服务。
