# 大数据稳定性与任务所有权契约（80阶段）

本文件供继续开发的 AI agent 阅读。适用网页、语义桥接和 MCP 渲染任务；它不是扩大输入范围或公开部署的授权。

## 不变量

1. 输入和科学准备：core/tree-input.js 是唯一解析器；core/gene-preparation.js 是唯一批次筛选/冲突统计输入转换；core/phyparts-engine.js 是唯一内置冲突统计实现；二者都由 core/input-worker.js 在独立 Worker 执行。主线程只接收合格云层子集、序列化统计输入及逐棵审计，不复制完整解析森林。
2. 同一事务：解析 → 验证 → 原生计算 → 完整状态提交。取消/错误回滚上一有效模型及控件；迟到消息不得重新提交。名称识别也纳入导入事务，不能在显示完成后继续无所有者计算。
3. 统计始终四类完整计算；两类显示只是呈现。样品不全的树仍按原定规则参与统计。缺外群、未知名称、无效格式等排除逐棵记录，不因性能改分母。
4. 完整云层超限时清除整个待绘云层并记录错误，统计仍完整计算；用户明确关闭云层后才允许导出物种树/饼图。不能抽样一部分后声称完整。
5. 只有自己的 Worker、任务令牌和进程组可取消。禁止 pkill/killall，禁止查询全机后按程序名杀进程。
6. 普通树、Dating树、云层及双树排版均按原评分/候选顺序协作执行；约24毫秒工作后让出主线程并检查取消。云层行位置缓存必须包含树对象身份、末端顺序、全部年龄、根年龄、起点和间距；未完成/取消的搜索不能缓存。缓存不是改变评分或科学数据的理由。
7. 饼图候选位置搜索必须复用 layoutPiePlacementSteps，逐候选提供中断边界；不得在协作渲染内改回同步穷举，也不能为了性能改变统计、坐标评分或最小可读半径。
8. 双树支持率布局必须通过 layoutConflictSupportSteps 协作执行；导入、MCP最终重绘与交互设置不能绕回同步搜索。取消新导入的对照树必须保留上一主树。
9. SVG导出必须等待设置和协作重绘完成后再克隆画布。计算中的树图及失败的设置排版不得作为完成图件导出；一致性测试也必须等待终态，不能通过忽略字体/坐标差异来放宽要求。
10. renderTree/renderCloudTree旧交互入口也必须启动或加入协作事务，不能内联耗尽生成器。MCP报告、上下两图逐图排版和原画布恢复必须await协作渲染。修改云图根年龄的treePL计算也属于可取消事务，失败不得提交新年龄。同步生成器耗尽仅用于冻结几何反例，不能回到生产交互。
11. 普通树、Dating树和云树的完整导出宽度硬上限为400 mm，双树冲突图为800 mm。四个版面必须共用同一个物理宽度与长宽比计算器；双树只把统一计算得到的树体宽度平均分给左右两棵树。自动长宽比、显式宽度和横向拉伸均不得越过当前版面的上限；接近上限时压缩横向树枝坐标，不缩小文字高度、不增减样品、不改变纵向间距或科学数据。用户于2026-11-04确认替代旧画布比例：完整样品名超过本图全部名称自然宽度中位数的1.25倍时，只横向压缩字形至该上限，短名称不变；双树两侧合并计算；此显示规则由figure-contract及render/tip-width统一执行。双树两列名称均很长时保留连线通道，以剩余正宽度分配树体，详见TIP_LABEL_WIDTH_CHANGELOG。其他文字与必要树体仍放不下时必须明确失败，禁止裁字、截断分组名或偷偷突破上限。网页序列化与MCP运行时均须再次断言当前版面的上限。

## 有界准入

|对象|当前安全边界|处理|
|---|---|---|
|单树上传文件|12,000,000 bytes|读文件前拒绝|
|单树解析文本|12,000,000 UTF-16 code units，最多1,000,000 tokens、200,000节点、深度512|解析器拒绝；Nexus扫描也受同一边界约束|
|交互单树绘图|1,500个末端|保留原树，超限明确拒绝，不剪样品|
|基因树集合上传文件/文本|120,000,000 bytes / 120,000,000 code units|完整批次准入；超限不使用部分结果|
|基因树集合|最多20,000棵、累计10,000,000节点|Worker内计数；超限整批失败|
|合格完整云层|累计30,000节点|不绘制部分云层，统计不抽样|
|Worker|单任务120秒|terminate，清除活动集合，拒绝迟到结果|
|网页导入/MCP绘图|600秒|取消本次任务，回滚或不提交图件|
|内置冲突统计|300秒|终止专属Worker；丢弃迟到消息；回滚上一有效状态|
|原生定年|treePL单棵30秒/批次300秒|专属进程组TERM，再KILL；等待回收|
|原生任务所有权|30秒无状态轮询|CLIENT_DISCONNECTED，自动取消|
|名称识别|客户端10秒；原生助手分别30秒；服务任务总计60秒|受管取消；保留已有内置名称规则回退，不改样品身份|
|任务容量|每引擎1个活动任务，64个保留结果/1小时；MCP绘图队列8|超额拒绝，不无界排队|

这些是分别测量的输入/绘图界限，不是“固定内存上限”。本机HTTP旧接口仍保留较大的传输上限以兼容历史客户端；JSON解码、浏览器DOM、字体和栅格化不能因此被称为硬性内存隔离。正式多租户/极端输入仍需容器级CPU/RAM配额、资源压力测试和流式协议。

## 原生计算生命周期

网页/MCP → core/native-client.js → 带编号的HTTP任务 → tools/native_jobs.py → process_supervisor.py → 独立 process_guardian.py → 引擎专属进程组。

- 正常完成：监护器也检查/停止仍存活的组内后代，回收后才返回退出码。
- 用户取消：发送任务令牌的 /cancel，状态为cancelling；回收后才为cancelled。
- 超时/所有者断连：设置同一个取消事件，走同一回收路径。
- 本机服务SIGKILL：监护器控制管道EOF，与服务线程/atexit无关，仍回收引擎组。
- MCP宿主SIGKILL：仅其私有页面服务启用父进程stdin所有权管道，断开后退出并回收原生执行；外部APP_URL共享服务不启用此管道，不受影响。
- 浏览器崩溃/断网：可能无法送出取消请求，30秒租约是兜底；任务不能继续无限运行。
- 取消确认失败：返回CLEANUP_PENDING/cleanup_pending，不冒充已停止；原生时限和租约仍有效。

监护器基于POSIX进程组，当前实测macOS arm64。Linux实现适用但本阶段未实机验收；Windows不保证此原生路径。刻意脱离进程组的第三方子进程、监护器自身被强杀、系统级崩溃/资源耗尽不在本机制的绝对保证范围。不可把这些边界写成“永远不会遗留任何进程”。

## 修改后强制验证

- 真实进程测试：取消、超时、成功主进程留下子进程、父服务SIGKILL，含忽略SIGTERM的后代；检查OS状态，不只查job JSON。
- HTTP任务：treePL cancel、总时限、无心跳租约；终态前ACTIVE为空、槽位释放、无部分result。
- MCP：三个引擎任务的deadline均发cancel并确认终态，页面和串行队列可继续使用。
- 私有运行时：浏览器启动失败、正常关闭与MCP宿主SIGKILL均检查OS中的已记录私有子进程退出；不得用关闭共享服务替代。
- Worker：主动取消、超时、迟到消息、file://异步准入失败、小树回退/批次禁止回退。
- 浏览器：1,500末端树仍有heartbeat，1,501明确拒绝且保留原模型；大基因树取消后Worker/native活动数为0；完整四类结果与有效树数一致。
- 真实73 MB/13,797树单独测试并记录输入hash、计数、最大UI heartbeat间隔、耗时、采样RSS、SVG及实际网页导出PNG。RSS采样不是精确峰值或平台通用基准。
- 运行 check-project、--integration、--native-science，保留日志/退出码/build_id。不得删除上述反例或降低门槛来过测试。

共享MCP/页面服务、公网服务、个人Skill不会随源码更新。运行入口及构建ID须分别核查；没有用户授权不得重启/部署。
