# 云树：使用已经定年的物种树

## 使用方法

在“云树 → 数据”中，先选择物种树输入类型，再上传文件：

- **未定年 ML 枝长树**：沿用原流程，先用 treePL 对物种树作示意定年，再处理基因树。
- **已定年物种树**：直接读取输入的节点时间，不重新定根，不对物种树再次运行 treePL，不改成默认根时间 10。
- 其他拓扑来源仍可用于节点饼图；不能将未经确认的共祖单位当成 ML 替换枝长来作云层定年。

已定年输入可选择年龄来源，并声明原文件的时间单位。时间单位仅说明输入数值含义，不会擅自换算数据；例如 MCMCtree 的原始单位可能是用户自定义的时间尺度，不能仅凭文件名猜测。

随后上传基因树，基因树仍需确认为 ML 替换枝长。它们由真实 treePL 计算，继承物种树的根年龄和完全相同后代样品集合的内部节点年龄；拓扑不一致的节点不会强行套用年龄。物种树的原始文本、注释和时间映射保持不变。

## 支持的时间信息

按文件内容解析，而不是依赖扩展名：

- BEAST 1、BEAST 2、StarBEAST 等常见 MCC Nexus：支持 translate 及节点时间注释。
- MCMCtree 常见 FigTree Nexus 时间树：通过时间枝长读取；HPD 区间不作为点估计时间。
- treePL Newick，以及等价的已定根超度量时间枝长树。

自动年龄来源按整树检查：完整 `height`，然后完整 `height_mean`，然后完整 `height_median`，最后是完整超度量时间枝长。不会在一棵树内混用几个年龄摘要，不会把支持率或 HPD 中点当作年龄。用户也可明确指定某一来源；改变来源后需重新上传文件。

对于很大或很小的根时间，求解器内部采用数值缩放，并将基因树结果恢复到输入物种树原单位。这不是重新定年物种树，也不是修改原始输入。

## 明确的限制与保护

- 输入必须是一棵汇总树；多树后验链请先生成 MCC 或其他汇总时间树。
- 检查样品唯一性、时间完整性、父子年龄顺序、正根年龄及时间枝长超度量性。
- 明确声明为无根的树不能作为已有定年参考直接使用。
- 当前基因 treePL 流程把末端固定在现在。带有非零末端年龄的化石或序列采样时间树暂不支持，程序明确拒绝，不会静默把末端归零。
- 格式兼容不等于所有软件历史版本均已测试；不包含只有节点编号或表格、缺少可解析时间树的任意文本输出。
- 已定年输入的化石校准状态由外部分析决定，软件不替用户推断；未经化石校准的示意时间仍不能当作真实分化年代。

饼图时间范围沿用这棵参考树的原始时间。重新设置单位、显示范围或阶梯化不会触发定年。导出 SVG 元数据分别记录物种树时间来源和基因树 treePL 校准来源。

## 验证入口

纯逻辑回归：`node --test tests/cloud-imported-dating.test.cjs`。

真实浏览器与后台回归：`npm --prefix mcp-server run test:cloud-imported-dating`。该测试使用独立测试浏览器，验证格式与错误输入、物种树不调用 treePL、真实基因 treePL、内置JavaScript冲突统计、共有类群校准和大时间单位还原；需本机具备项目的 treePL 运行环境，冲突统计不再需要Java或外部PhyParts。

格式参考：[BEAST TreeAnnotator](https://beast.community/treeannotator)、[MCMCtree 官方源码](https://github.com/abacus-gene/paml/blob/master/src/mcmctree.c)、[treePL 官方说明](https://github.com/blackrim/treePL/wiki/Quick-run)。
